To the Fairyland

Game Design Document

Created by Yucan Chen, Shai Crespo

Introduction

This document describes a game called "To The FairyLand", which is designed to be a simple, Top Down Adventure 2D Pixel RPG. The game will employ sprite-based animation, tiled backgrounds, collision detection, AI, efficient memory management, render threading, and more basic 2D game techniques. The game is story based and will utilize a dialogue systems and UI.

Technology

To The FairyLand will be developed for Browsers using the Wolfie2D game engine, developed by Richard McKenna for teaching 2D Game Programming. WebGL will be used as the underlying rendering technology. Cakewalk Sonar will be used for developing the music. Sound effects and Artwork will be developed using various editing tools.

Back Story

The Fall of Humanity: Humanity fought a war against 3 Monster Kingdoms (Lycans, Ratkins, Corvus) and lost. The 3 Monster Kingdoms carved up human land, resulting in the deaths of most humans. The few survivors are scattered across the land.

The Antagonists: The human kingdom was decimated by 3 Great Lords who initiated the battle. The human survivors are entirely outmatched and do not have the power to defeat them.

The Current Threat: Humans must hide as the Monster Kingdoms are actively sending troops to conquer the remaining territory and hunt down the survivors.

The Destination & Hope: "TheFairyLand" is located far outside the borders of the three monster kingdoms. Because the fairies did not participate in the attack on the human kingdom, they are humanity's last hope. The overarching goal of the game is to survive the journey to Fairyland and beg for their assistance.

The Protagonist: The player plays as Fate. A child playing pretend. He is a "fake knight" wearing a suit of armor who greatly admires the human expedition team. His origins are unknown, where the player is introduced to Fate living in a wooden shelter alone on a Snowy mountain. Fate comes across a dying member of the Human Expedition team who entrusts him with the task of reaching Fairyland and asking for their help to save humanity.

Objective

The player (Fate) must complete the Human Expedition team's mission to reach the Fairyland and ask for their help to save humanity. However, the 3 Monster Kingdoms will not let him do this easily, and will actively try to stop him.

Gameplay

The game has the style and gameplay resembling RPG Maker games. The game is played from a top down perspective. Movement is done in a strict cardinal system with no diagonal movement. Interacting with elements of the world and other characters will prompt a dialogue system which displays the text at the bottom of the screen with a close up sprite of the character (if there is one). The player proceeds through sections by solving puzzles and progressing the story through interactions. The player will have to avoid enemies and obstacles, but there will not be a combat system. Should the player take damage, they will lose health which they can heal via items in their inventory (accessed through the menu). If the player loses all their health, they will be sent back to the last checkpoint they reached.

Level Design

The game will have 6 Acts, each with a unique environment and set of challenges. Each act will either act as an expositiory chapter to build the world and story, or introduce a new enemy corresponding to the area or monster kingdom.

Act 1 - will be the Snowy Mountain, which serves as a tutorial and introduction to the game mechanics and story. This area is where the player learns about the human expedition team and their mission.

Act 2 - will be the Human Village, which introduces the player to NPC interactions and builds the world. This area has basic puzzles and weak enemies which set the baseline for the game's difficulty. This area is where the player is introduced to enemies from The Lycan Kingdom.

Act 3 - will be the Rat Forest, which introduces more difficult puzzles and stronger enemies. This area is where the player is introduced to enemies from The Ratkin Kingdom.

Act 4 - will be the Crow Nest, which introduces stealth mechanics and the faster/stronger enemies. This area is where the player is introduced to enemies from The Corvan Kingdom.

Act 5 - will be a vast desert landscape, which introduces smarter enemies which can hide their presense underground. These enemies are the most powerful, and can only be detected right before they unburrow and when they are above ground. This area is where the player is introduced to the desert centipede enemies.

Act 6 - will be the FairyLand, as this is the final act of the game. This area is wont have additional challenges, and will serve to conclude the story.

Controls

This game will be played using keyboard. Once started, use the following:

  • W - Move Up
  • A - Move Left
  • S - Move Down
  • D - Move Right
  • UP-ARROW - Move Up (same as W)
  • LEFT-ARROW - Move Left (same as A)
  • DOWN-ARROW - Move Down (same as S)
  • RIGHT-ARROW - Move Right (same as D)
  • J/Z - Interact/Confirm
  • K/X - Cancel
  • C - Open Menu/Inventory
  • ESC - This pauses the game and presents a pop-up window to the player asking them to continue when they are ready. If a game is not in progress, ESC does nothing.

Graphical User Interface

Splash Screen

The splash screen GUI simply presents a game logo and a Start button for the user to press when they are ready to play. Upon pressing it, a brief scripted sequence is played explaining a little about Spike and the back story for the game. While playing the message "Press ESC to Skip" should be displayed at the bottom of the screen. If pressed, the game should immediately start.

Main Menu

  • New Game - If a game is in progress, first we'll pop up a dialog to make sure the user really wants to quit the current game. If we conclude the user really wants to start a game, then the game state is reset and begun.
  • Continue - If a game is in progress, this option will allow the player to resume from where they left off.
  • Level Select - If pressed, the game will display a screen to select which level to play.
  • Controls - If pressed, the game will display an info screen that includes a description of all game controls.
  • Help - If pressed, the game will display an info screen with the game's backstory, the credits, and the cheat codes (if the player has unlocked them). The cheat codes will be available for developers and unlocked for players after completing the game.

Level Selection Screen

The main game has 6 Acts, which will be unlocked sequentially as the player completes each one. The level selection screen will display the 6 Acts in a list, with the locked Acts grayed out and unselectable until they are unlocked. For developers, all Acts will be unlocked from the start.

Controls Screen

The controls screen will list the controls as well as have a visual diagram depicting a keyboard with the corresponding keys marked. The menu will be viewable from the Main Menu as well as in the in-game pause menu.

  • W - Move Up
  • A - Move Left
  • S - Move Down
  • D - Move Right
  • UP-ARROW - Move Up (same as W)
  • LEFT-ARROW - Move Left (same as A)
  • DOWN-ARROW - Move Down (same as S)
  • RIGHT-ARROW - Move Right (same as D)
  • J/Z - Interact/Confirm
  • K/X - Cancel
  • C - Open Menu/Inventory
  • ESC - This pauses the game and presents a pop-up window to the player asking them to continue when they are ready. If a game is not in progress, ESC does nothing.

Help Screen

The help screen will first explain the backstory of the game if players want to reread it. Below the backstory will be the developer credits which will have names and links to the team members' Github Pages. Below the credits will be a list of cheat codes for developers. The list of cheat codes will always be available for developers, and will be unlocked after completing the game for players.

In-Game Screen

There will not be an overlaying HUD. However, when the player is near an interactable object or NPC a prompt may appear to notify them. When a player is interacting with an object or NPC, a dialogue box UI element will appear at the bottom of the screen. If the dialogue box has appeared to display the words spoken by a character or NPC, then an enlarged sprite will appear behind the dialogue box to indicate the speaker(s).

In-Game Menu

This is the menu that appears when the player presses the C for their Inventory during gameplay. This is a seperate menu that is not the same as the pause menu that appears when the player presses ESC. This menu will show the player their current health and the items they have in their inventory. Time will stop while this menu is open, but the player will not be considered to be "paused" and thus the pause menu will not be accessible while this menu is open.

Pause Menu

This is the menu that appears when the player presses the ESC key during gameplay. This is a seperate menu that is not the same as the in-game menu that appears when the player presses C. This menu will have options to resume the game, view the controls, or return to the main menu. Time will stop while this menu is open, and the player will be considered to be "paused" and thus the in-game menu will not be accessible while this menu is open.
